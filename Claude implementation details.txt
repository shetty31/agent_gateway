This architecture is not built via blind AI generation; it is orchestrated using a strict, Staff-level tripartite workflow:
1. The Architect (Human TPO/Gemini): We define the strict volumetric RPM policies, JSON schema contracts, and generate the foundational Python logic.
2. The Code Reviewer (Human TPO): The logic is manually reviewed and staged in the local IDE to ensure absolute adherence to system boundaries.
3. The Execution Engine (Claude Code CLI): Claude acts strictly as the autonomous test-driven development (TDD) engine. It spins up the local servers, fires synthetic IoT payloads, reads terminal tracebacks, and autonomously patches integration bugs to ensure the 8 Python components communicate flawlessly in real-time.
Together, this system generates simulated physical IoT traffic, executes volumetric RPM rate-limiting, routes anomalous hardware data into a quarantine, buffers concurrent traffic in RAM, transforms data via event-driven triggers, and exposes the results for programmatic querying via an MCP adapter.
The Real-World Analogy: The Highly Regulated Restaurant
Imagine you are the owner of an exclusive, highly regulated restaurant.
• The Customers: Hundreds of people trying to get in at once.
• The Bouncer: Checks IDs at the door to keep out unregistered troublemakers (Hard Drops), but if an approved VIP shows up wearing sneakers, they are softly routed to a holding area instead of being kicked to the curb (Schema Quarantine).
• The Hostess: Checks each guest's entry frequency. If a guest tries to barge in and out 60 times a minute, they are temporarily locked out to protect the kitchen from chaos (RPM Quota).
• The Waiting Area: Where approved guests sit so they don't overwhelm the chefs in the kitchen all at once (VRAM Buffer).
• The Meticulous Accountant: The staff in the back office who instantly process receipts the second they arrive, attaching a strict chain-of-custody tracking form, and organizing them into flexible boxes (Event-Driven ETL).
• The Financial Auditor: An auditor who can rapidly scan those complex boxes on demand to calculate exact profits and system health (Programmatic BI).
Here is exactly how this architecture is implemented and mechanically tested in Python.
The Step-by-Step Architecture & Execution Loop
1. The IoT Sensor Load Generator (load_tester.py)
• The Analogy: A bus pulling up and dropping off hundreds of customers at once.
• The Technical Mechanics: A multi-threaded script designed to simulate concurrent, polymorphic MedTech IoT sensors, validating hardware backpressure by firing 100+ JSON payloads per second (RPS).
• Claude's Execution Role: Claude executes the script in the terminal, monitors the OS for dropped packets or socket timeout errors, and dynamically patches the concurrent thread count if it breaches local OS limits.
2. The FastAPI Gateway & Soft Validation (gateway.py)
• The Analogy: The Bouncer checking IDs and quarantining VIPs with dress-code violations.
• The Technical Mechanics: A local web proxy using FastAPI. It evaluates incoming physical hardware traffic based on strict schema contracts. If authentication fails, it executes a 403 Hard Drop. If a payload contains scientific anomalies (e.g., a broken thermometer reading) but passes security, it executes "Soft Validation," routing the raw JSON to a ./quarantine/ folder.
• Claude's Execution Role: Claude boots the uvicorn server in the background, crafts malformed JSON payloads using terminal curl commands, fires them at the endpoint, and reads the HTTP response codes to verify the Quarantine routing logic is flawless.
3. The Volumetric RPM Circuit Breaker (redis_mock.py)
• The Analogy: The Hostess checking entry frequency to prevent kitchen chaos.
• The Technical Mechanics: A local Redis-emulated counter. Before the Gateway approves a request, it checks the equipment's Requests-Per-Minute (RPM) quota. If exceeded (simulating a hyperactive, broken sensor), it instantly drops the connection with a 429 error, ensuring zero wasted downstream compute.
• Claude's Execution Role: Claude fires rapid sequential requests specifically designed to breach the baseline RPM limit. It monitors the terminal output to guarantee the threshold-breaking request returns a strict 429 Hard Drop.
4. The VRAM Batcher & Async Buffer (virtual_vram_batcher.py)
• The Analogy: The Waiting Area. If you send 100 orders to the chef simultaneously, the kitchen catches fire.
• The Technical Mechanics: Emulating Apache Kafka, this implements memory buffers using Python's asyncio.Queue. It holds approved sensor payloads in volatile RAM and flushes them to disk (/bronze_raw/) in dynamic batches based on time and volume limits to prevent storage I/O exhaustion.
• Claude's Execution Role: Claude forces a massive synthetic traffic spike and reads the terminal logs to verify that the queue flushes dynamically without blocking the main FastAPI thread.
5. Event-Driven Orchestration & Data Lineage (event_listener.py)
• The Analogy: The Accountant who processes receipts the exact second they are printed.
• The Technical Mechanics: Replacing inefficient cron-polling, this uses Python's watchdog library to hook into the OS. The exact millisecond a file lands in Bronze, it triggers an ETL script that injects strict provenance metadata (e.g., original_bronze_file_id, processing_timestamp) for unbreakable FDA-compliant traceability.
• Claude's Execution Role: Claude synthetically drops a file into the /bronze_raw/ directory, checks the terminal logs to confirm the watchdog OS event fired instantly, and verifies the metadata was successfully injected.
6. NoSQL Document Handling & Programmatic BI (kpi_report_generator.py)
• The Analogy: Storing data in flexible boxes rather than rigid filing cabinets.
• The Technical Mechanics: The system reshapes valid observations into a strict tripartite schema (data_package, data_cube, data_description) and saves them as deeply nested NoSQL JSON files in /silver_harmonized/. A BI script then queries these flat files directly to calculate hardware KPIs (e.g., volumetric drop rates).
• Claude's Execution Role: Claude runs the BI script against the nested JSONs. If deep nesting causes a Python KeyError, Claude reads the terminal traceback, uses its internal file-edit tool to fix the parser logic, and re-runs the script until it outputs a clean KPI terminal report.
7. The MCP Interoperability Server
• The Analogy: The "Drive-Thru API" that acts as a universal adapter for external delivery drivers.
• The Technical Mechanics: To achieve FAIR data principles, an Anthropic Model Context Protocol (MCP) Server adapter is configured over the /silver_harmonized/ directory, allowing external enterprise systems and BI tools to securely query the clean NoSQL documents without vendor lock-in.
• Claude's Execution Role: Claude spins up the MCP server, emulates a completely blind external AI agent, and executes queries against the server to prove the machine-readable payload contracts are functioning securely.
8. The System Orchestrator & Global Telemetry (bootstrap_manager.py)
• The Analogy: The General Manager of the Restaurant. They don't cook the food or seat the guests, but they unlock the doors, turn on the lights, coordinate the staff radios, and immediately know if a fire breaks out in the kitchen.
• The Technical Mechanics: A bootstrap shell script (or Python orchestrator) that launches all independent system components in the strict, correct dependency order (e.g., Redis-mock must be running before the Gateway boots). It establishes a global telemetry layer, intercepting the stdout and stderr logs from all scripts and streaming them into a single, unified observability console.
• Claude's Execution Role: Claude writes the multi-process orchestration script. It then intentionally kills one of the child processes (like the Event Listener) to verify that the Orchestrator correctly catches the SIGTERM signal, logs a fatal error traceback, and gracefully shuts down the rest of the ecosystem rather than leaving zombie processes running in the background.
